# CLAUDE.md

Guidance for AI coding agents working in this repository. Human contributors
should read [CONTRIBUTING.md](CONTRIBUTING.md) instead — it says the same things
with more reasoning.

## What this is

Arturo: a macOS full-screen slideshow viewer for a folder of photographs. Swift
6, SwiftUI with three AppKit bridges, XcodeGen-owned project structure, local SPM
package for design tokens, Swift Testing for unit tests.

## Structure truth

`project.yml` is the **only** source of truth for project structure.
`Arturo.xcodeproj` and `Generated/` are gitignored build outputs regenerated by
`xcodegen`.

- Never edit `Arturo.xcodeproj` or anything in `Generated/`. The edit is lost on
  the next generate.
- After adding, moving, or deleting any source file, run `make generate`. XcodeGen
  discovers sources by directory, so a file that is not regenerated into the
  project is not compiled, and a missing symbol error will point somewhere
  misleading.
- The deployment target is declared twice and both must agree: `project.yml` for
  the app, and `Packages/DesignSystem/Package.swift` for the package. Drift
  produces a deployment-target mismatch at compile time.

Run `make generate` and then check `git status`. It must leave a clean tree. If
`Generated/` or the project file show a diff after a bare `make generate`, the
manifest is non-deterministic and that is a bug.

## Commands

| Command | Meaning |
|---|---|
| `make verify` | The gate. Format, lint, build, unit tests. Exit 0 = done. |
| `make test` | Unit suite only, fast. |
| `make test-ui` | UI smoke lane. Slow, needs ad-hoc signing. |
| `make generate` | Regenerate the project from `project.yml`. |
| `make format` | Fix formatting. The usual remedy for a red `verify`. |
| `make doctor` | Environment check against the build floor. |
| `make install` | Release build → `/Applications/Arturo.app`. |

`make verify` is the Definition of Done. Do not report work complete without it
green and its output pasted.

## Conventions

- **SwiftUI by default.** AppKit only in `Sources/App/Bridges/`, one concern per
  file, for exactly three things: `NSOpenPanel`, the full-screen transition, and
  the `NSEvent` key monitor. Anything else needs an ADR.
- **Tokens, not literals.** Colour, spacing, and type come from `DesignSystem`.
  No hex values or magic numbers in views.
- **State:** `@Observable` models, injected via the initializer, Environment-scoped.
- **Tests:** Swift Testing for unit tests. Red before green — the test must be
  shown failing before the fix. Deterministic over timing-dependent: inject the
  clock (`RotationLoopTests`) rather than sleeping.
- **Read-only.** Nothing copies, moves, or edits a user's photograph. Nothing
  writes to disk except `UserDefaults` (`arturo.holdSeconds`, `arturo.columns`,
  `arturo.fillsFrames`).

## Things that will silently break

- **Decoding must stay off the main actor and at display size.** The whole
  performance story rests on `CGImageSourceCreateThumbnailAtIndex` with a pixel
  ceiling rather than a full-resolution bitmap. The cache cap is 9 frames, by
  count rather than by bytes, so memory is predictable on mixed-resolution
  folders.
- **The UI lane cannot run unsigned.** The system launches the test runner and
  refuses an unsigned bundle; that lane signs ad-hoc. If `make test-ui` dies at
  launch while unit tests pass, check that seam before anything else.
- **`pkill -x Arturo` in the UI lane is load-bearing.** An installed copy shares
  the bundle id and keeps the keyboard, so the test-launched build never receives
  the key events the suite asserts on.
- **Adding a file without `make generate`** produces a confusing "cannot find
  type" error rather than a missing-file error.

## What is intentionally absent

Do not "helpfully" add these without discussing it, and do not describe the
project as having them:

- **No performance baselines and no signposts.** ADR-005 records this as a known
  gap. The memory and main-thread guarantees are real, but they are enforced by
  construction rather than by test.
- **No App Sandbox.** Required only for Mac App Store distribution. Arturo reads
  a folder the user picks, so it needs no file-access entitlement. TCC still
  gates Desktop, Documents, Downloads, iCloud Drive, and network volumes.
- **No release automation in this repo yet.** Signing and notarization are
  documented in `docs/distribution.md` but not wired into a workflow.

## Deployment floor

macOS 26.0, and it is one floor rather than two: the app runs on macOS 26, and
macOS 26 is what the build host and CI run, so the floor is runtime-testable. The
code itself uses no API newer than macOS 15, so lowering the target would be a
one-line change in `project.yml` plus `Packages/DesignSystem/Package.swift`,
followed by a test pass on the older OS. Do not lower it without that test pass.
